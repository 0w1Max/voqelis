# Пунктуация Voqelis — A/B-испытание

Статус: изолированное исследование. Production не меняем.

## Суть
Текущий RUPunct иногда ставит запятые внутри неверного синтаксического блока. Для выбора нового решения требуются разнообразные диктовки, размеченные вручную. Из одного предложения нельзя доказать пользу модели.

## Кандидаты
- RUPunct small INT8 — существующий baseline.
- GigaAM v3 E2E CTC — уже существующий в проекте экспериментальный аудиозависимый адаптер, с ограничением 25 с и проекцией на оригинальные слова RNNT.
- Horizon-Labs punctuation-restoration-small ONNX — отдельная оценка потребления RAM и задержки.
- Внешний LLM — только отдельное разрешение на отправку личного текста.

## Локальные входные данные
Формат MANIFEST: JSON-массив объектов с id (string), reference_words (исходная транскрипция RNNT), reference_punctuation (ручная разметка тех же самых слов), duration_seconds (длительность речи).
Формат предсказаний: JSON-объект case-id -> {text: punctuated-text, latency_ms: измеренная задержка}.
Файлы содержат приватные тексты. Хранить вне Git/веб-каталога в директории с правами 0700. Не публиковать реальные медицинские записи в GitHub, промптах и stdout.

## Пример использования
PYTHONPATH=src .venv/bin/python -m tools.compare_punctuation --manifest /private/punctuation-gold.json --candidate gigaam-e2e=/private/gigaam-e2e.json --rupunct-model-dir /var/lib/voqelis/rupunct-model-v1 --output /private/punctuation-report.json --min-cases 30

Этот инструмент не запускает внешние API. Ему можно передать существующие кандидатские предсказания или запустить локальный RUPunct. Отчёт содержит агрегаты и идентификаторы, а не тексты. Выходной файл создаётся с правами 0600 без перезаписи.

## Gate качества
Минимум 30 (желательно 50) неповторяющихся сравнимых диктовок с проверенным эталоном. Нужны comma F1, period F1, ошибки границ, недопустимые изменения слов (ноль), p50/p95 задержки, пик RAM. Нельзя переносить выводы текстового benchmark напрямую на аудио.
Кандидат с изменёнными лексическими словами отвергается. Для E2E сначала проецировать пунктуацию на слова RNNT с существующей защитой, оценивать долю отказов проекции.
Для VPS 1 vCPU / 2GB RAM испытания запускать ограниченно и не менять продакшн-процесс. Только после измерений и живого теста возможен переключаемый выпуск.
