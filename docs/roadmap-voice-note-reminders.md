# Roadmap · Voqelis: голосовые заметки и напоминания

Статус: **запланировано**, реализация в будущем; production-код не меняется.
Дата фиксации: 2026-10-26. Приоритет: после работ по точности пунктуации,
стабилизации «Фактов дня» и первых интеграций Workflow Core.

## Ценность для пользователя

Пользователь диктует запись и время напоминания. Voqelis сохраняет содержание
заметки, распознаёт намерение «напомни», просит подтвердить дату/время и в
подтверждённый момент присылает сообщение в личный чат с ботом.

Пример:

- Пользователь: «Напомни мне сегодня в 18:30 начать работать над проектом».
- Бот: «Напомнить **26.10.2026 в 18:30 по Москве**: начать работать над
  проектом? [Сохранить] [Изменить время] [Отмена]».
- При наступлении времени: «🔔 Напоминание · Начать работать над проектом.
  [✅ Выполнено] [⏰ Отложить 10 минут]».
- При голосовой заметке без времени: бот сохраняет заметку и может предложить
  «Добавить напоминание», не назначая время автоматически.

## Техническое ограничение Telegram: «Избранное»

**Обычный Telegram Bot API не предоставляет боту доступ к чату пользователя
с самим собой (Saved Messages) для автоматической отправки.** Вызов
\`sendMessage(chat_id=user_id)\` доставляет сообщение в приватный чат
пользователя с ботом, а не в «Избранное». Источники:
- https://core.telegram.org/bots/api#sendmessage
- https://core.telegram.org/api/saved-messages

MVP: приватный чат Voqelis (можно закрепить его) с push-уведомлениями.
При желании пользователь может переслать полученное сообщение в «Избранное»
вручную. Нельзя ради обхода ограничения незаметно авторизовывать Telegram
user session через MTProto/прашивать SMS-коды, облачные пароли и хранить
сессию пользовательского аккаунта на VPS. Возможность ручного шаринга из
Mini App — отдельная UX-задача, не автоматическая доставка.

## Scope V1: пять обязательных сценариев

1. **Голосовой ввод:** запись вида «Завтра в 18:30 позвонить…»; новая заметка
   или напоминание к существующей заметке. Источник слов — GigaAM RNNT,
   детерминированный парсер времени + evidence. LLM может предложить
   извлечение, но НЕ назначает время и НЕ отправляет сообщения автономно.
2. **Подтверждение:** пользователь видит нормализованную локальную дату,
   время, временную зону и текст. Неоднозначности («вечером», «в шесть»,
   прошедшее сегодня 18:30) требуют выбора/исправления; никакого
   автоматического «значит завтра» без подтверждения.
3. **Постоянное хранение:** запись и расписание переживают перезапуск.
   Черновик не является активным напоминанием; переход в состояние
   scheduled только после подтверждения.
4. **Доставка:** фоновый scheduler проверяет задания и посылает
   \`sendMessage\` в авторизованный PRIVATE chat_id; в сообщении кнопки
   «Выполнено», «Отложить» и «Отключить». Не использовать чат врача
   и не публиковать личный текст в сторонних местах.
5. **Управление:** список активных напоминаний, просмотр, редактирование
   даты/времени и текста, отмена, история отправки. Нет смешения с Planner:
   создание задачи в Planner — отдельная подтверждённая операция.

## Архитектура

\`\`\`text
Telegram voice/text -> existing ASR/GigaAM -> Intent+TimeEvidence
                                         -> Preview+Confirmation
                                         -> NotesService (optional link)
                                         -> ReminderService
                                         -> RemindersStore(SQLite)
                                         -> Scheduler/DeliveryWorker
                                         -> Telegram Bot API (personal bot chat)
\`\`\`

- Новый модуль \`voqelis.reminders\` с \`domain\`, \`time_parser\`, \`service\`,
  \`store\`, \`scheduler\`, \`telegram_delivery\`.
- На старте отдельная \`reminders.sqlite3\`, независимо от \`notes.sqlite3\`,
  \`planner.sqlite3\` и \`day_facts.sqlite3\`. Связь с note_id разрешает
  service-layer, дополнительно сверяя owner_id. Позднее Workflow Engine
  сможет использовать то же действие \`schedule_reminder\`.
- Хранить нормализованное расписание в UTC (\`scheduled_at_utc\`),
  \`timezone\` (IANA, для текущего Voqelis по умолчанию
  \`Europe/Moscow\`), исходное пользовательское выражение даты/времени,
  \`note_id?\`, приватный recipient chat_id, текст уведомления, статус,
  версию записи и журнал попыток доставки. Не добавлять часы только как
  строку "18:30" без даты.
- Статусы: \`draft\`, \`scheduled\`, \`sending\`, \`sent\`, \`done\`,
  \`snoozed\`, \`cancelled\`, \`failed\` (точная модель уточняется при
  реализации). В БД enforce owner_id и atomic compare-and-swap/claim.
- Цикл отправки запускается вместе с сервисом и восстанавливается после
  restart/crash, с lease для незавершённых заявок, ограниченными retries и
  backoff на Telegram 429/5xx. Один инстанс V1, отсутствие параллельных
  несогласованных воркеров. systemd supervised.
- **Delivery guarantee:** Telegram Bot API не даёт общего end-to-end
  idempotency key. При падении между успешным HTTP sendMessage и
  записью результата теоретически возможна повторная доставка; не
  обещать абсолютного exactly-once. Принять controlled at-least-once
  и дедупликацию по локальным попыткам, честно покрыть этот случай тестами.
- Безопасность: 0600 для SQLite и резервных копий, per-user authorization,
  не логировать личные заметки и токены, кнопки с токеном/версией,
  проверка private chat, ограничение частоты, не отправлять содержимое
  психотерапевтических заметок во внешние LLM без согласия.
- Использовать \`ZoneInfo\`; проверить смену даты/часового пояса и летнее
  время для зон, где оно есть. Учитывать часы VPS в UTC; нельзя считать
  время из текста временем в часовом поясе сервера.

## Приёмочные тесты (gate перед production)

- «сегодня в 18:30»/«завтра в 18:30»/«послезавтра»/без даты;
  неоднозначные времена, уже прошедшее локальное время;
- «в 18:30 напомни закончить проект» и отдельная заметка + выбор
  «Напомнить»; слова и временные якоря не изменяются LLM;
- создание двух напоминаний одним пользователем и изоляция второго
  пользователя; отмена, редактирование, отложить, выполнено;
- возврат после рестарта с pending/scheduled/sending;
- Telegram timeout, 429 Retry-After, 5xx, невалидный chat_id,
  блокировка бота пользователем, повторные callback;
- предел памяти и CPU на VPS (1 vCPU, 2 GB RAM), отсутствие нарушения
  ASR/Planner/Notes; резервные копии, схема миграции;
- временно управляемые часы / fake Telegram API, затем единственный
  осознанный live-test с конкретным временем на реальном VPS.

## Порядок выполнения

1. Утвердить UX и детерминированные правила времени в RFC.
2. Создать отдельные SQLite Store, Scheduler, Service и тесты
   без подключения к production Telegram.
3. Подключить команды/кнопки, проверить voice routing с Notes и Planner.
4. Проверить пересылку напоминания в личный чат бота, перезапуск,
   лимиты ресурсов, fail-safe rollback.
5. Позже добавить событие \`schedule_reminder\` в Voqelis Studio как
   **разрешённое встроенное действие** для созданных шаблонов:
   конструктор не должен исполнять произвольные задачи или код.

## Explicitly NOT in V1

Автоматическая отправка в «Избранное» через обычный Bot API; хранение
пользовательских MTProto-сессий; сторонние сервисы уведомлений;
переписывание Planner; AI-решения о времени без подтверждения;
гарантия абсолютной однократности при сбое сети.
