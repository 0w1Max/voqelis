# Voqelis Workflow Core V0 — работающий прототип без подключения к боту

Цель: доказать, что «Факты дня» и другая таблица могут выполняться одним
детерминированным движком, не создавая отдельный Python-модуль на каждую
структуру. Прототип реализован в пакетах voqelis.workflows.spec и
voqelis.workflows.runtime, с тестами.

Шаблон содержит идентификатор, неизменяемую версию, заголовок, список
вопросов/полей и разрешённые экспорты. Реализованы типы «один текст» и
«несколько текстовых пунктов». Не реализованы пока произвольные условия,
медицинские интерпретации, выполнение пользовательского кода, запись в базу,
UI-конструктор и Telegram Mini App.

Движок: start_workflow → submit → [advance для повторяемого списка] →
review → (begin_edit/submit или cancel_edit) → confirm. Все операции требуют
проверенного user_id и актуального токена; при смене конфигурации под той
же версией fingerprint меняется и сессия отклоняет новую схему. Слова
пользователя движок не исправляет; текст из ASR и деление на предложения
поступают в него только через отдельный адаптер.

Незавершённые и сохранённые данные пользователей сейчас **не мигрируем**.
Workflow Core не включён ни в Planner, ни в Notes, ни в DayFacts: до
выпуска нужны отдельная SQLite-персистентность, тесты миграций, права
пользователей и общие адаптеры Telegram/Mini App.

Нефункциональные требования:
- никакого eval, произвольного SQL или пользовательского Python;
- строгие допустимые поля конфигурации, типы и ограничения размеров;
- хранение исторических схем по version + fingerprint;
- пользовательская правка и подтверждение до сохранения;
- при интеграции аудио прикреплять к исходному шагу токеном до ASR;
- конфиденциальные данные не передавать третьим лицам автоматически.

Это foundation для следующего этапа Workflow Store + Telegram adapter,
а не самостоятельная готовая Mini App.
